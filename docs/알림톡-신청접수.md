# 신청 접수 알림톡 — 구조 · 템플릿 · 바꾸는 법

고객이 인투마케팅 신청서(홈페이지 · 앱 · 프로그램 · 디자인 · 영상 · SNS · 블로그·리뷰)를 내면,
신청서에 적은 휴대폰 번호로 **「신청 접수 완료」 알림톡**이 자동으로 갑니다.

> 🔴 **이 저장소는 공개입니다.** API 키 · 비밀값 · 템플릿 ID 를 이 문서에 적지 마세요.
> 🔴 **2026-10-24 부터 발송 통로는 하나입니다.** 예전 계획(`apply-notify` 함수 · `mkt_alimtalk_log` 표 ·
> `APPLY_HOOK_SECRET`)은 쓰지 않으며 저장소에서도 지웠습니다. 다시 만들면 신청 1건에 알림톡이 2통 갑니다.

---

## 1. 어떻게 움직이나

```
신청서 제출 (apply/form.js · apply/index.html · hakwon/apply → requests 표, center='mkt')
  → DB 트리거 requests_alimtalk_receipt_t → 함수 requests_alimtalk_receipt()
       └ mkt_receipt_plan(신청 건) 이 «보낼지 · 무엇을» 판단 (보내지 않는 건은 이유를 기록)
  → Edge Function send-alimtalk  (블로그센터 알림과 «같은 함수 한 벌» · 1회용 열쇠로 부름)
  → 솔라피 → 카카오 → 고객 카카오톡   (sms_fallback 을 켠 템플릿만 실패 시 문자로 대신)
  → alimtalk_log 에 결과 기록 (ref = 'request:<신청 id>')
```

| 무엇 | 어디 |
|---|---|
| 트리거 · 판단 함수 | `supabase/migrations/20261024120000_mkt_request_received_unify.sql` (이 저장소) |
| 발송 함수 `send-alimtalk` | Supabase(qkvebwxewttqtcryfycy) Edge Functions — 🔴 원본 코드는 이 저장소에 없습니다 (블로그센터 쪽) |
| 템플릿 ID · 변수 · 승인 값 · 문자 대체 | `settings` 표 key='blog' → `alimtalk_templates.request_received` |
| 발신프로필(pfId) | `settings` 표 key='blog' → `alimtalk_pf.intomarketing` |
| 솔라피 키 · 대체발송 번호 | Edge Functions → Secrets : `SOLAPI_API_KEY` · `SOLAPI_API_SECRET` · `SOLAPI_SENDER` |
| 발송 기록 | `alimtalk_log` (kind = `request_received`) |

**보내지 않는 경우** (`alimtalk_log` 에 `skipped` 와 이유가 남습니다)

| 이유 | 뜻 | 남기는 곳 |
|---|---|---|
| `NOT_CUSTOMER` | 관리자가 어드민에서 직접 넣은 건 (`details.등록 경로 = 관리자 직접 입력`) · 로그인 없이 들어온 건 | 트리거 |
| `MATERIAL_FOLLOWUP` | 계약 뒤 「제작 자료」 제출 — 신청이 아니므로 | 트리거 |
| `DAILY_LIMIT_PHONE` / `DAILY_LIMIT_USER` | 같은 번호 24시간 5통 · 같은 계정 24시간 10건 초과 (남의 번호를 적는 장난 방지) | 트리거 |
| `NO_VALUE:<변수>` | 그 신청 종류를 템플릿 값으로 바꿀 수 없음 (예: 「기타」) | 트리거 |
| `NOT_APPROVED:<변수>=<값>` | 심사 때 승인받은 값(`enum`) 밖 | 트리거 |
| 휴대전화 번호가 아닙니다 · 템플릿 미승인 · 키 없음 · 이미 보낸 건 | | send-alimtalk |

번호가 아예 없는 건과 학원지원센터(`center='esc'`) 신청은 기록 없이 넘어갑니다.

## 2. 템플릿

### 지금 쓰는 것 · 바꿀 것

| | 예전 「신청접수안내」 | 새 「인투마케팅_신청접수」 |
|---|---|---|
| 승인 | 2026-10-15 | 2026-10-24 (이은총 님 확인) |
| 변수 | `#{상호}` `#{서비스명}` | `#{고객명}` `#{신청분야}` `#{접수번호}` `#{접수일시}` |
| 다루는 종류 | 5 (앱 · 프로그램 없음) | 7 |
| 문자 대체발송 | 꺼짐 | 켬 (`sms_fallback: true` · 대표 번호 010-3918-4119) |

트리거는 `settings` 의 `vars` 목록을 보고 «그 템플릿이 쓰는 변수만» 채웁니다.
그래서 **템플릿을 바꿀 때 코드를 고치지 않습니다** — `settings` 한 줄만 바꿉니다 (4절).

### 새 템플릿 문구 (솔라피 등록본)

| 항목 | 값 |
|---|---|
| 발신프로필 | **인투마케팅** 채널 (2026-10-08 승인) |
| 템플릿명 | `인투마케팅_신청접수` |
| 형태 | 강조표기형 |
| 강조표기 보조문구 | `인투마케팅` |
| 강조표기 제목 | `신청이 접수되었습니다` |
| 카테고리 | 서비스이용 > 이용안내/공지 |

**본문**

```
#{고객명}님, #{신청분야} 신청이 접수되었습니다.

- 접수번호: #{접수번호}
- 접수일시: #{접수일시}

담당자가 신청 내용을 확인한 뒤, 영업일 기준으로 접수 순서대로 연락드립니다.

신청 내역은 아래 「신청 내역 확인」에서 보실 수 있습니다.
문의: 010-7318-1790
```

**버튼** — 웹링크 `신청 내역 확인` → `https://intomarketing.co.kr/my/` (모바일 · PC 같은 주소)

**변수가 채워지는 값** (`mkt_receipt_plan`)

| 변수 | 예시 | 값 |
|---|---|---|
| `#{고객명}` | 홍길동 | 담당자 이름 → 없으면 상호 → 없으면 「고객」 |
| `#{신청분야}` | 홈페이지 제작 | `mkt_apply_field_name(kind)` : 홈페이지 제작 · 앱 제작 · 프로그램 제작 · SNS 채널 · 그래픽 디자인 · 영상 제작 · 블로그 · 리뷰 |
| `#{접수번호}` | 1019-X9L7 | 홈페이지 신청서는 화면의 「신청 번호」, 나머지는 신청 건 id 앞 8자리(대문자) |
| `#{접수일시}` | 2026년 10월 21일 오후 3:05 | 저장된 시각 (한국 시간) |

**심사 통과 원칙**
- 손님이 직접 신청한 데 따른 **정보성** 안내입니다. 「할인」 「무료」 「이벤트」 「지금 신청」 같은 말을 넣지 않습니다.
- 버튼 이름 · 제목에는 변수를 쓰지 않습니다.
- 구체적인 영업시간은 넣지 않았습니다 (10/21 결정). 시간을 적으면 운영 시간이 바뀔 때마다 재심사이고, 「09:00 처리」가 지켜야 할 약속이 되기 때문입니다.
- 🔴 `#{신청분야}` 에 들어갈 수 있는 값은 **심사 때 승인받은 값**뿐입니다. `settings` 의 `enum.신청분야` 에 그 값을 그대로 적어 두면,
  목록 밖의 값은 트리거가 보내지 않고 `NOT_APPROVED` 로 남깁니다.

## 3. 새 템플릿으로 바꾸기 (한 번만)

| 순서 | 할 일 | 누가 |
|---|---|---|
| 1 | 솔라피 콘솔에서 새 템플릿 ID(KA01TP…)와 «승인된 신청분야 값» 확인 | 행정 |
| 2 | 대체발송 번호 `SOLAPI_SENDER` 가 들어 있는지 확인 — `send-alimtalk` 에 `{"check":true}` 를 보내면 `sender:true/false` 로 알려 줍니다 (값은 안 보여 줌) | 기술 |
| 3 | 아래 SQL 로 `settings` 바꾸기 (템플릿 ID 는 SQL Editor 에서만 넣고 이 저장소에는 적지 않음) | 기술 |
| 4 | 본인 계정으로 **홈페이지의 신청서**(예: /apply/sns/)에서 1건 → 카톡 도착 · `alimtalk_log` 의 `sent` 확인 → 시험 건 정리 | 기술 |

```sql
-- 3. 새 템플릿으로 (예전 것은 previous 에 남깁니다)
update public.settings
   set value = jsonb_set(value, '{alimtalk_templates,request_received}',
     jsonb_build_object(
       'id',       '<새 템플릿 ID>',
       'name',     '인투마케팅_신청접수',
       'channel',  'intomarketing',
       'approved', '2026-10-24',
       'vars',     jsonb_build_array('고객명', '신청분야', '접수번호', '접수일시'),
       'enum',     jsonb_build_object('신청분야', jsonb_build_array(
                     '홈페이지 제작', '앱 제작', '프로그램 제작', 'SNS 채널',
                     '그래픽 디자인', '영상 제작', '블로그 · 리뷰')),   -- 🔴 승인받은 값만 남기세요
       'sms_fallback', true,
       'previous', value->'alimtalk_templates'->'request_received'))
 where key = 'blog';
```

🔴 4번 시험은 **어드민의 「새 주문」으로 넣으면 안 됩니다** — 그 건은 「등록 경로 = 관리자 직접 입력」이 붙어 `NOT_CUSTOMER` 로 건너뜁니다.
홈페이지 신청서로 내면 관리자 계정이어도 손님 신청과 똑같이 보내집니다.

**되돌리기** — `previous` 로 돌려놓으면 예전 템플릿으로 바로 돌아갑니다.

```sql
update public.settings
   set value = jsonb_set(value, '{alimtalk_templates,request_received}',
                         value->'alimtalk_templates'->'request_received'->'previous')
 where key = 'blog' and value->'alimtalk_templates'->'request_received' ? 'previous';
```

## 4. 확인하는 법

```sql
-- 이 신청 건에 무엇이 나갈지 «보내지 않고» 미리 보기
select r.created_at, r.kind, public.mkt_receipt_plan(r) - 'to' as plan
  from public.requests r where r.center = 'mkt' order by r.created_at desc limit 10;

-- 최근 신청 접수 알림 20건
select created_at, status, error, vars, ref
  from public.alimtalk_log where kind = 'request_received' order by created_at desc limit 20;
```

`failed` 가 보이면 `error` 칸에 솔라피가 돌려준 이유가 들어 있습니다.
가장 흔한 원인은 ① 템플릿 문구 · 변수 이름 불일치 ② pfId 가 다른 채널 것 ③ 발신번호 미등록입니다.

## 5. 🔴 `send-alimtalk` 을 고칠 때

이 함수는 블로그센터 알림(블로거 17종)과 인투마케팅 고객 알림이 함께 씁니다.
2026-10-24 에 이 저장소 작업으로 **배포본(v6)** 에 두 가지를 더했습니다 — 원본 저장소에도 같은 변경이 들어가야 다음 배포 때 지워지지 않습니다.

1. 템플릿에 `sms_fallback: true` 가 있고 `SOLAPI_SENDER` 가 있을 때만 `disableSms: false` (나머지는 전처럼 `true`)
2. `{"check":true}` 결과에 `sender: true/false` (대체발송 번호가 들어 있는지)

원본 쪽에서 이 두 가지가 빠진 채 다시 배포되면 → 문자 대체발송만 꺼지고 알림톡은 그대로 나갑니다 (안전한 쪽으로 망가집니다).
